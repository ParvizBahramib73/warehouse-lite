# انبار من — Warehouse Lite (PWA Prototype 0.1.7)

نسخه آزمایشی 0.1.7 **بدون دیتابیس ابری، بدون سرور تجاری و بدون وابستگی npm** برای پخش مواد اولیه قنادی شهر همدان.

## قابلیت‌هایی که اکنون پیاده شده‌اند

- کالا با واحد عدد / کیلو (ذخیره در واحد صحیح عدد/گرم) و تبدیل بسته
- تأمین‌کننده، سند خرید و افزایش موجودی
- مشتری، محله، تلفن و روز مراجعه، جستجو و صفحه‌بندی فهرست مشتریان، نمایش گردش کامل حساب
- فاکتور فروش چندقلمی با مسیر سریع‌تر ثبت، حفظ پیش‌نویس هنگام رفتن به افزودن مشتری و تمرکز خودکار روی فیلد بعدی
- فاکتور فروش قابل ویرایش با ثبت گردش اصلاحی و کسر اتمیک موجودی
- ویرایش، غیرفعال‌سازی و حذف دائمیِ امن کالا، مشتری و تأمین‌کننده (حذف دائمی فقط بدون سابقه)
- ویرایش سند خرید با اصلاح گردش موجودی و ابطال خرید در صورت کافی‌بودن موجودی باقی‌مانده
- ویرایش و ابطال دریافت وجه با حفظ سابقه؛ ابطال فاکتور با کنترل دریافت‌های بعدی
- دریافت اولیه هنگام فروش و دریافت جداگانه؛ مانده مشتری
- فاکتور برنددار «علی‌فاکتور» با نام صادرکننده علی و محل فعالیت همدان
- جداکننده سه‌رقمی خودکار برای مبلغ‌ها هنگام تایپ، با ارقام فارسی و حفظ جای نشانگر تایپ
- چینش خوانا و چپ‌به‌راست برای فیلدهای مبلغ تومان
- اعتبار پایین برنامه: «ساخته‌شده برای داداش علی»
- اشتراک‌گذاری تصویر باکیفیت فاکتور از منوی اشتراک‌گذاری اندروید؛ پیام‌رسان‌های نصب‌شده و سازگار مانند واتساپ، تلگرام، روبیکا و ایتا قابل انتخاب‌اند
- پیش‌نمایش فاکتور، چاپ / ذخیره PDF از مرورگر
- خروجی دستی **رمزگذاری‌شده AES-GCM** و ورود رمز، پیش‌نمایش و بازیابی داده‌ها
- Service Worker برای بازشدن بدون اینترنت پس از یک‌بار بارگذاری موفق
- برنامه مسیر ویزیت بر اساس روز هفته و محله، با ثبت نتیجه مراجعه (خرید، عدم خرید، عدم دسترسی یا پیگیری مجدد) و تاریخ پیگیری بعدی
- گزارش سود ناخالص برآوردی بر پایه میانگین موزون بهای خرید؛ ذخیره بهای خرید هنگام صدور فاکتورهای جدید و بازسازی تقریبی برای فاکتورهای قدیمی در صورت وجود سابقه خرید
- داشبورد با پیشنهاد پیگیری مشتری بر اساس آخرین فاکتور و مانده حساب ثبت‌شده
- جستجو و صفحه‌بندی ۲۵ ردیفی برای فهرست کالاها، خریدها، تأمین‌کنندگان، فروش‌ها و مشتریان؛ مسیر ویزیت و گزارش سود نیز صفحه‌بندی دارند
- ارتقای IndexedDB به نسخه ۲ با جدول ویزیت‌ها و ایندکس‌های جستجوی سوابق؛ بکاپ‌های قدیمی نسخه ۱ همچنان قابل بازیابی‌اند
- UI فارسی/RTL با طراحی یکپارچه، ناوبری موبایل، فرم‌های لمسی و چیدمان responsive برای موبایل، تبلت و دسکتاپ
- سایدبار دسکتاپ چسبیده به لبه راست viewport

## هنوز پیاده نشده‌اند

- مرجوعی جزئی با رسید برگشت مستقل، مدیریت چک وصول‌نشده، تاریخ انقضا، پیامک، سود خالص پس از هزینه‌های عملیاتی، اشتراک مستقیم فایل PDF (فعلاً تصویر PNG از طریق Share و PDF از مسیر چاپ مرورگر)، احراز هویت کاربران، همگام‌سازی ابری و مهاجرت سرور.
- بهینه‌سازی مسیر بر اساس مختصات و ترافیک/مسیریابی GPS پیاده نشده است؛ مسیر فعلی بر اساس روز و محله گروه‌بندی می‌شود.
- سود گزارش‌شده سود ناخالص برآوردی است، نه گزارش حسابداری رسمی یا سود خالص.
- مدیریت چک و تخصیص دریافت‌های عمومی به فاکتورهای مشخص هنوز کامل نیست.
- ابطال فاکتور در صورت وجود دریافت وجه یا تسویه بعدیِ مبهم عمداً متوقف می‌شود؛ ابتدا باید وضعیت دریافت‌ها تعیین تکلیف شود.

## مقیاس داده و محدودیت فعلی

- فهرست‌های اصلی در رابط کاربری به صفحه‌های ۲۵ ردیفی، جستجو و فیلتر تقسیم شده‌اند تا تعداد عناصر هم‌زمان در صفحه محدود بماند.
- داده‌ها هنوز در شروع برنامه از IndexedDB به حافظه مرورگر خوانده می‌شوند؛ برای ده‌ها هزار رکورد یا استفاده هم‌زمان چند دستگاه، مرحله بعد باید خواندن صفحه‌ای با cursor/index و سپس API/سرور باشد. صفحه‌بندی فعلی به معنی صفحه‌بندی سمت دیتابیس نیست.
- مسیر ویزیت و نتیجه هر مراجعه به‌صورت رکورد مستقل ذخیره می‌شود و در فایل پشتیبان رمزگذاری‌شده نیز قرار می‌گیرد.

این برنامه برای ساده‌تر شدن مدیریت روزانه کسب‌وکار علی طراحی و توسعه داده شده است.

## اجرای محلی

پیش‌نیاز: Python 3 یا هر وب‌سرور ایستا. فقط با HTTPS یا localhost، نه file:// .

```bash
cd warehouse-lite-pwa
python3 -m http.server 8765
```

روی همان دستگاه مرورگر: http://localhost:8765

اگر از گوشی به سرور روی کامپیوتر با IP خصوصی متصل شوید، نصب PWA و WebCrypto ممکن است به خاطر نیاز به HTTPS کار نکنند. برای آزمایش روی گوشی از نشانی HTTPS معتبر استفاده کنید.

## نصب روی Android

1. نسخه HTTPS را در Chrome Android باز کنید؛ حداقل یک بار کاملاً آنلاین بارگذاری کنید.
2. منوی مرورگر → Add to Home screen / Install app (بسته به مرورگر).
3. پس از نصب حالت هواپیما را فعال کنید و بازشدن برنامه و ثبت تراکنش با داده **آزمایشی** را بررسی کنید.
4. یک فایل رمزگذاری‌شده را دانلود کنید، ذخیره‌شدن آن را بررسی کنید و آن را در یک مرورگر/پروفایل آزمایشی بازیابی کنید.

## نگهداری در GitHub

- این پروژه را در **مخزن جداگانه** نگهدارید؛ نیاز به دسترسی به مخزن وب‌سایت شخصی نیست.
- فایل‌های `*.wlbackup` و داده‌های مشتریان را هیچ‌وقت Commit یا منتشر نکنید.

- GitHub مخزن داده یا بکاپ نیست؛ میزبانی HTTPS ایستا را جدا انتخاب کنید.

## انتقال به سرور در آینده

- از کد واحد دامنه و شناسه‌های UUID استفاده شده تا API و سرور بعداً اضافه شود.
- فرمت `warehouse-lite-encrypted` نسخه‌دار است و برای انتقال یک‌باره می‌توان آن را در سمت client رمزگشایی و در API معتبر ثبت کرد.
- همگام‌سازی دوطرفه و حل تعارض هنوز طراحی و پیاده‌سازی نشده است؛ انتقال به سرور نیازمند پروژه و تست جداگانه است.

## اصول داده و ریسک

- «تومان» عدد صحیح، «کیلو» در پایگاه به «گرم» صحیح تبدیل می‌شود.
- موجودی از تغییرات اتمیک و ثبت گردش کالا پشتیبانی می‌کند.
- ویرایش فاکتور، خرید و دریافت با کنترل موجودی و مانده حساب انجام می‌شود؛ ابطال به‌صورت تغییر وضعیت و ثبت گردش معکوس است، نه پاک‌کردن تاریخچه.
- رمز خروجی را حداقل ۸ کاراکتر و ترجیحاً عبارت طولانی انتخاب کنید. **فراموشی گذرواژه بازیابی را غیرممکن می‌کند.**
- خروجی فایلی تضمین نمی‌کند دانلود موفق بوده: حتماً آن را خارج از گوشی و در دستگاه دیگر آزمایش کنید.
- برنامه بدون حساب کاربری/رمز ورود است؛ محافظت از قفل دستگاه و پروفایل مرورگر ضروری است.

## انتشار عمومی آزمایشی با GitHub Pages

در مخزن `ParvizBahramib73/warehouse-lite` با شاخه پیش‌فرض `master`:

1. در Settings → Pages، گزینه Source را روی **GitHub Actions** قرار دهید.
2. فایل‌ها و پوشه‌های همین پروژه را در ریشه مخزن قرار دهید.
3. با هر push به `master`، workflowهای کیفیت و انتشار اجرا می‌شوند.
4. پس از موفقیت workflow انتشار، برنامه در نشانی `https://parvizbahramib73.github.io/warehouse-lite/` در دسترس خواهد بود.

تمام مسیرهای برنامه نسبی هستند تا در زیرمسیر GitHub Pages کار کنند. فایل‌های `dist/` خروجی build هستند و نباید جداگانه commit شوند.

**حریم داده:** مخزن عمومی فقط کد و فایل‌های ثابت برنامه را نگه می‌دارد. اطلاعات مشتری، تأمین‌کننده، فاکتور، پرداخت و فایل‌های `.wlbackup` فقط روی دستگاه کاربر هستند و نباید وارد GitHub شوند. برای این پروژه مجوز استفاده مجدد (LICENSE) تعیین نشده است.

**محدودیت:** GitHub Pages فقط میزبان فایل‌های ثابت است؛ دیتابیس یا فضای ابری برای اطلاعات عملیاتی ایجاد نمی‌کند. ذخیره‌سازی محلی و پشتیبان‌گیری دستی همچنان مسئولیت دستگاه/کاربر است.
