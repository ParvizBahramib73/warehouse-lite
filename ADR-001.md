# ADR-001: Single-device offline PWA and manual encrypted backup

- Status: Accepted for a disposable-data pilot, not production financial records
- Date: 2026-11-23
- Owner: Product owner (user); primary tester: brother (business owner)

## Context
A nontechnical pastry-ingredient distributor in Hamadan needs a mobile-first free prototype for one Android device. Internet may be unreliable and no Windows computer or paid hosting is available. Future server migration is desired.

## Options
1. React/Capacitor APK + native SQLite: more robust platform integration, higher build/release complexity.
2. Dependency-free web PWA + IndexedDB: fastest iteration and easy offline evaluation; browser data retention limits.
3. Cloud web app with hosted database: requires reliable external service, costs, auth, and network architecture now.

## Decision
Choose (2) for an early controlled pilot with synthetic data. Keep domain and persistence as modules; use stable UUIDs, ISO timestamps, integer Toman, integer grams/pieces, explicit inventory movement ledger, atomic IndexedDB write transactions, and versioned encrypted portable backups. No sync or server now. Repository contains only code and fixtures, never client data or backups.

## Consequences
- One writable device. No live multi-device sync.
- IndexedDB is browser-origin data, not a permanent vault. Clearing site data, device loss, browser issues can destroy records.
- Installable only over HTTPS or localhost with a compatible browser and Service Worker support.
- Printing PDF uses the browser's print/save-as-PDF mechanism, not guaranteed direct messaging-app share.
- Incoming checks, returns, stock correction, server sync, invoices customization, local notifications and some accounting reports are deferred.
- Future server migration should use a shared domain layer and a versioned migration from backup JSON into a server DB. Not automatic.

## Validation gates
1. Purchase increases stock once, sale decreases once, overselling aborts the whole write.
2. Data survive app close and offline restart on actual Android Chrome.
3. Encrypted export+restore on second test profile/device with count and totals reconciled.
4. Persian/RTL mobile UX test with business owner.
5. Do NOT hold the sole copy of financial records in the browser before backup restore, corrections/returns, device security and risks are accepted.
